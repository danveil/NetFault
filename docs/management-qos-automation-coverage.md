## Matrix vocabulary

M = `10.MANAGEMENT.ppt`; Q = `11.QoSrv.ppt`; A = `12.NETWORKAUTO.ppt`, all from the archive above. C = concepts; K = configuration familiarity; V = verification. Before 3S these three families had no dedicated Academy modules: existing case commands support general evidence habits, not SNMP, QoS or controllers. Actions below describe **current delivered coverage and remaining work**:

- **COMPLETE** applies only to an explicitly bounded existing skill, never an entire subject.
- **ACADEMY / TOUCH PRACTICE** means taught and/or exercised locally, not device execution.
- **DEVICE COMPANION** means an original optional brief, currently **UNEXECUTED**.
- **FUTURE ENGINE/LAB** is a proposal requiring separate authorization.
- **DEFER** includes material only mentioned or too weakly supported for substantive implementation.

## Corrections and supplementary technical references

The supplied decks determine topic selection; these primary references check semantics, not academic weighting or device execution:

- M23 and the revision shorthand use UDP 162 broadly: [RFC 3417 §3.2](https://www.rfc-editor.org/rfc/rfc3417.html#section-3.2) distinguishes command responders (161) and notification receivers (162).
- Stratum is a time-source hierarchy, not routed IP hop count. [RFC 5905 §7.3](https://www.rfc-editor.org/rfc/rfc5905.html#section-7.3) identifies 16 as unsynchronized; reference-clock stratum 0 is not an ordinary valid received server stratum. The lesson separates configuration intent and status.
- [RFC 5424 §6.2.1](https://www.rfc-editor.org/rfc/rfc5424.html#section-6.2.1) supports severity meanings; Cisco-style threshold examples are authored instructional material, not captured RFC-format output.
- Q39 incorrectly places ECN at Layer 2; Q40's own IP diagram and [RFC 3168](https://www.rfc-editor.org/rfc/rfc3168) support the IP-field distinction. [RFC 2475](https://www.rfc-editor.org/rfc/rfc2475.html) separates marking, conditioning and per-hop behavior. DSCP alone never establishes end-to-end quality; CoS-to-DSCP mapping is policy-dependent.
- [RFC 7426](https://www.rfc-editor.org/rfc/rfc7426.html) supports control/forwarding responsibilities. The course's reactive first-flow story and leaf-spine shorthand are not universal SDN or literal one-physical-hop rules.
- [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html) distinguishes JSON literal types; [RFC 9110 §9](https://www.rfc-editor.org/rfc/rfc9110.html#section-9) defines HTTP method semantics. Stateless requests do not forbid stored resources; safe GET semantics do not mean no logging or other incidental effects.
- [NIST SP 800-145](https://csrc.nist.gov/pubs/sp/800/145/final) distinguishes cloud service/deployment models. Cloud is not necessarily off-premises. The course's tool push/pull and agent classifications are introductory patterns, not universal product limitations.

No obsolete SNMP cipher is recommended merely because it appears in a slide. Voice/video numerical targets remain labeled course examples, not universal service contracts.

## Remaining gaps and rough completion estimate

These families now have substantive conceptual and structured reasoning coverage, **not complete practical coverage**. The curriculum still has broader IPv6/OSPFv3/dynamic addressing, dynamic NAT/PAT, IPsec/WAN, security/design variants, authentic configuration, tool operation and transfer to unfamiliar networks. Even within these decks, hardware/design, detailed troubleshooting-strategy comparison, image/password recovery, precise QoS policies and real controller/model authoring remain gaps.

Revised working ANT-focused **learning-support estimate: approximately 88% (rough range 83–93%)**, versus the user's historical ~84%. This is an explicit product-planning judgment, not a measured syllabus percentage, examination prediction or mastery score. No official weighting exists. To make the estimate inspectable, the working rubric is: current-source conceptual support 33/35; guided/independent learning support 24/25; bounded executable breadth 22/25; availability of practical preparation/verification paths 9/15 = **88/100**. The last category scores preparation availability, **not executed device competence**; external execution remains unverified. Ratings are judgmental and should be revised against a confirmed rubric and authentic practice evidence, not incremented per lesson.

The increase reflects three previously missing dedicated learning families with original examples, 14 graded activities and explicit verification boundaries. Executable breadth receives no increase in 3S. Seven lessons do not eliminate the practical and advanced gaps above; changing the denominator to independently demonstrated device skills would produce a substantially lower estimate.
