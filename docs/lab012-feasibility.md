A deterministic one-to-one static mapping can avoid a session table beyond configuration. A single per-probe mapping could bound a later dynamic exercise, but cannot teach concurrency/exhaustion or faithfully support persistent translation diagnostics without event rules. “GRE is stateless” and “static NAT mapping is permanent” do not mean either already works in this engine.

Current `forward` retains one original packet source; `connectivity` finds a physical/VIP destination owner. NAT would require a mutable address context, reverse translation and valid global delivery, including explicit routing/proxy-ARP boundaries. Replacing strings in `ping` or `show` output is insufficient. Routes remain necessary even when a mapping exists. Reusing `evaluateAcl` requires a distinct classification purpose and tests protecting LAB009's implicit-deny/filter/local-origin rules; the existing /24-or-any/two-entry subset is not a general NAT ACL implementation.

A future derived logical edge is coherent **only** if it keeps three results: local tunnel operational eligibility; directional outer endpoint delivery/pair matching; inner route/next-hop delivery. Remote matching must not be used as a fake local up/down oracle. Underlay lookup excludes tunnel-derived routes; overlay forwarding preserves inner addresses; return processing repeats independently. No need to serialize GRE bytes for a hop-level model, but MTU/fragmentation, TTL, keepalives, counters and encryption cannot be claimed. Existing physical-link and directly linked static-next-hop validation would need explicit logical-interface support; do not pretend a drawn dashed edge already provides it.

## 6. Challengers and comparison

NTP/discovery is the strongest small challenger: MR has direct configuration/verification names, and a wrong NTP peer could distinguish service failure from IP reachability. However, useful synchronization proof needs a bounded service/stratum/reachability model and truthful time semantics; CDP alone offers a weaker user-service incident. IPv6 has strong X1 support but needs address-family and neighbor foundations. QoS needs load/queue/time evidence; automation fits Academy plus actual local tools; IPsec needs security associations and independent validation. DHCP snooping/DAI/802.1X require leases, bindings or authentication state absent today. None is promoted solely because it is uncovered.
